# BIM 轻量化 WebGPU 浏览系统需求说明书

## 1. 项目引言 (Introduction)

本项目旨在构建一个基于 Web 技术的纯前端 BIM (Building Information Modeling) 模型轻量化浏览系统。核心目标是利用最新的 **WebGPU** 技术实现高性能的 3D 渲染，并支持行业标准格式（如 IFC、STEP）的解析与展示。项目将遵循“Github 高星项目标准”，强调极致的工程质量、现代化的 UI 设计以及完全的容器化交付。

## 2. 核心功能需求 (Functional Requirements)

### 2.1 模型导入与轻量化 (Import & Lightweighting)
*   **多格式支持**: 支持用户从本地导入 **IFC** (.ifc) 和 **STEP** (.stp/.step) 格式的 BIM/CAD 模型文件。
*   **前端解析**: 采用 WebAssembly (WASM) 技术在浏览器端直接解析复杂模型数据，无需后端转换服务，保护用户数据隐私。
*   **轻量化处理**:
    *   自动化几何合并 (Geometry Merging) 以减少 Draw Calls。
    *   实例化渲染 (Instanced Rendering) 优化重复构件（如相同的窗户、螺丝）。
    *   自动移除不可见或微小构件（可选配置）。

### 2.2 WebGPU 核心渲染 (WebGPU Rendering)
*   **渲染引擎**: 基于 **Three.js (r160+)** 的 `WebGPURenderer`，利用 GPU 计算管线（Compute Shaders）提升大数据量下的渲染性能。
*   **交互浏览**:
    *   支持标准的轨道控制器 (Orbit Controls)：旋转、平移、缩放。
    *   支持构件拾取 (Raycasting/Picking)：点击构件高亮并显示属性信息。
    *   剖切分析 (Clipping)：支持 X/Y/Z 轴向的模型剖切查看内部结构。
*   **视觉效果**:
    *   基于物理的渲染 (PBR) 材质。
    *   环境光遮蔽 (SSAO) 或简单的阴影效果增强立体感。

### 2.3 用户界面与交互 (UI/UX)
*   **现代化布局**: 采用 **Tailwind CSS** + **Shadcn UI** 构建“未来感”界面，包含深色模式、玻璃拟态效果。
*   **模型结构树**: 左侧提供模型构件层级树（Model Hierarchy），支持通过树状图控制构件的显示/隐藏。
*   **属性面板**: 右侧展示选中构件的详细 BIM 属性（Metadata）。
*   **性能监控**: 实时展示 FPS、Draw Calls、显存占用等 WebGPU 性能指标。

## 3. 技术架构与选型 (Architecture & Tech Stack)

鉴于“纯前端项目”及“WebGPU”的要求，架构设计如下：

### 3.1 技术栈 (Stack)
*   **开发框架**: **React 18** + **TypeScript** (强类型保障工程质量)。
*   **构建工具**: **Vite** (极致开发体验)。
*   **UI 组件库**: **Shadcn UI** + **Tailwind CSS** (符合 user_rule.md 中拒绝原生 HTML 及追求美观的要求)。
*   **3D 引擎**: **Three.js** (主要使用 WebGPURenderer 模块)。
*   **模型内核**:
    *   **IFC 解析**: `web-ifc` / `web-ifc-three` (WASM)。
    *   **STEP 解析**: `occt-import-js` (OpenCascade WASM port)。

### 3.2 目录结构 (Directory Structure)
```
src/
├── assets/             # 静态资源
├── components/         # 通用 UI 组件 (Button, Panel...)
├── core/               # 3D 核心逻辑
│   ├── bim/            # BIM 解析器 (IFC/STEP Loader)
│   ├── engine/         # WebGPU 渲染引擎封装
│   └── materials/      # 自定义 WebGPU 材质
├── layouts/            # 页面布局
├── stores/             # 状态管理 (Zustand: 管理选中构件、模型树)
├── types/              # TS 类型定义
├── utils/              # 工具函数
├── App.tsx             # 根组件
└── main.tsx            # 入口
```

## 4. 交付与部署 (Delivery & Deployment)

严格遵循 `user_rule.md` 的 Docker 交付标准。

### 4.1 容器化方案
*   **Docker All-in-One**: 虽然是纯前端项目，仍需提供 `docker-compose.yml`。
*   **服务定义**:
    *   `frontend`: 基于 Nginx 的静态资源服务容器。
*   **构建流程**:
    *   Dockerfile 采用 Multi-stage build。
    *   Stage 1 (Builder): `node:20-alpine`，运行 `npm ci` 和 `npm run build`。
    *   Stage 2 (Runner): `nginx:alpine`，挂载构建产物到 `/usr/share/nginx/html`。

### 4.2 运行指南
```bash
# 一键启动
docker compose up --build
# 访问地址
http://localhost:3000
```

## 5. 模块详细设计 (Module Design)

### 5.1 核心模块：WebGPUViewer
封装 Three.js 的初始化逻辑，处理 WebGPU 上下文丢失与恢复。
*   **输入**: Canvas DOM 元素。
*   **输出**: 渲染循环、相机控制器、场景图(Scene Graph)。
*   **关键点**: 需检测浏览器对 WebGPU 的支持情况，若不支持需（优雅降级）提示用户或回退到 WebGL（若时间允许，但本项目重点在 WebGPU）。

### 5.2 核心模块：BIMLoader
*   **策略模式**: 定义 `ILoader` 接口，`IfcLoader` 和 `StepLoader` 分别实现该接口。
*   **WebWorker**: 解析过程必须在 WebWorker 中运行，避免阻塞 UI 主线程（解析大模型时尤为重要）。

### 5.3 核心模块：UIOverlay
*   **Toolbar**: 顶部工具栏（打开文件、重置视角、剖切开关）。
*   **HierarchyTree**: 虚拟滚动列表（Virtual Scroll）展示成千上万的构件节点，保证 UI 流畅度。

## 6. 风险与对策 (Risks)

*   **WebGPU 兼容性**: WebGPU 目前仅在 Chrome/Edge 最新版提供良好支持。
    *   *对策*: 项目启动时进行环境检测，并提供明确的浏览器版本要求提示。
*   **STEP 格式解析**: STEP 格式解析在前端非常重（计算量大）。
    *   *对策*: 仅支持适量大小的 STEP 文件（<50MB），并在 UI 上显示加载进度条。

---
**注**：本设计严格遵守“零 Mock 核心逻辑”原则，模型解析均为真实 WASM 运行时解析；UI 设计将严格遵循“现代未来感”标准。
